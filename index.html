1. 背景引言：为什么需要 vla_test 分支？

TeleFuser 是中国电信人工智能研究院（Tele-AI）开源的高吞吐多模态扩散生成与实时流式计算推理框架。在早期阶段，TeleFuser 的主要重心集中于标准视频生成（如 Wan2.1、LTX-Video）以及流式世界模型（LingBot-World、Abot-World）。这些模型典型的推理范式是：用户发起一次性的文本/图像输入，经过耗时较长、多步 Denoise 的生成过程，返回完整视频或音频文件。

然而，随着具身智能（Embodied AI）与视觉-语言-动作大模型（Vision-Language-Action, VLA，如 LingBot-VLA v2）的兴起，传统的“无状态、批处理”推理服务遇到了根本性挑战：

  • 交互模式演变：从单次 Request-Response 演变成多步、有状态、低延迟的持续闭环交互会话（Session）。
  • 动作时序性与抢占性：机械臂控制必须具备严格的时间衰减（Age Check）、TTL 机制，并在新观测到达时支持对过时动作序列的优雅抢占（Supersede）。
  • 仿真环境解耦：机械臂控制通常对接 RoboTwin、MuJoCo 或真实机器人本体，若服务端直接绑定具体的物理引擎（如 SAPIEN/Vulkan/ROS），会导致推理服务器环境极为臃肿且不可维护。

基于上述需求，开发者建立了 vla_test 分支。历经近两个月的持续迭代，不仅圆满完成了 LingBot-VLA v2 的高性能推理与服务化，更推动了 TeleFuser 整体架构在会话管理、动作空间语义化与仿真解耦上的重构升级。

2. vla_test 演进全景：关键提交与四阶段技术突破

通过检查 vla_test 自初始化以来的全部提交记录，整个演进历程可清晰划分为四个阶段：

阶段一：基线构建与严格对齐 (7月下旬 - 8月上旬) f964169 (Init) ➔ 87960ac (Base Support) ➔ 8d03aa0 (Strict Parity) ➔ 3c996d6 (Trim Training Code) ⬇ 阶段二：服务工程化与 CUDA Graph 突破 (8月中旬 - 8月下旬) 3b49c71 (Native Service) ➔ 878aa1b (CUDA Graph Denoise) ➔ ff2f0f7 (Batch Camera) ➔ f02ec54 (Release Suite) ⬇ 阶段三：RoboTwin 仿真适配探索与痛点反思 (8月下旬 - 9月上旬) af644c4 (RoboTwin Adapter) ➔ 4e19bf3 (Remote Contract) ➔ 7801f53 (Action Chunks) ⬇ 阶段四：架构质变——通用语义化 VLA 会话与仿真解耦 (9月中旬) 4e44652 (Semantic Space) ➔ d6383a4 (Replica-Backed Pool) ➔ 9504db8 (Generic WS) ➔ 733aad3 (Retire Legacy)

阶段一：基线引入、显存瘦身与严格精度对齐（2026.07.28 ~ 2026.08.05）

此阶段的目标是将官方的 LingBot-VLA v2 6B 模型以最轻量的方式引入 TeleFuser，建立黄金标准。

  • f964169 feat: lingbot-vla-v2 init 与 87960ac feat: add LingBot VLA v2 base inference support：初始化模型代码骨架，引入 Qwen3-VL 视觉/语言编码器与动作去噪 DiT。
  • 8d03aa0 test(vla): establish official upstream parity：建立官方上游比对测试。在 BF16 精度下完成了 38 个关键层激活张量的逐层验证，达成严格的 max_abs = 0.0 绝对对齐。
  • 3c996d6 refactor(vla): trim training-only runtime code 与 2d40ee2 refactor(vla): prune legacy LingBot model code：大刀阔斧剥离上游训练专用的冗余代码与废弃权重，确立推理专用精简目录。
  • 3b49c71 / 953ec3f / 442106c：构建单卡原生结构化动作推理服务，并优化首版单卡调度时延。

阶段二：首期合并、CUDA Graph 动静结合加速与全自动化评测（2026.08.06 ~ 2026.08.27）

在完成 PR #28 合并后，工作重心转向工业级吞吐优化与发布级质量保障。

  • 878aa1b feat(vla): add CUDA Graph action denoising：关键性能拐点。由于 VLA 输入包含动态长度的多模态视觉提示词，而动作去噪循环（Action Denoising Loop）是固定 Shape（如 50 x 55）。团队创造性地采用“动态视觉 Prefix 走 Eager 模式 + 固定动作去噪循环录制为 CUDA Graph”的动静结合机制，消除了高频小算子的 Kernel Launch 开销，大幅压低推理延迟。
  • ff2f0f7 perf(lingbot-vla-v2): batch camera preprocessing：将头部（High）、左手腕（Left Wrist）、右手腕（Right Wrist）三路相机的预处理合并批处理，减少显存搬移。
  • 348b8ca / 3f9bfe8 / 34b98f9：优化 SDPA 注意力机制，解决 Rotary Embedding 和 BF16 视觉插值在不同后端下的细微漂移问题。
  • 1eafa09 / 839a776：引入 TorchAO 与 bitsandbytes 在线量化支持（INT8 / NF4 / FP8），使 6B 模型能够平稳运行于更低显存卡型上。
  • f02ec54 / 326b2d5：固化全自动化发布验证套件（Release Validation Suite），涵盖严苛的对齐、基准与故障容灾测试。

阶段三：RoboTwin 仿真适配探索与反思（2026.08.31 ~ 2026.09.08）

为了验证策略在模拟机械臂上的真实控制效果，团队开展了仿真适配：

  • af644c4 / 4e19bf3 / 7801f53：构建了基于 RoboTwin MessagePack 协议的专用动作服务器，支持远端推理与动作分块（Action Chunks）流水线调度。
  • 痛点暴露与反思：在实践中发现，将 MessagePack RPC、RoboTwin 的专用坐标系硬编码进推理端，导致服务端产生了对下游仿真环境的紧耦合；一旦接入新机械臂（如 ALOHA、Franka）或新仿真器（MuJoCo、IsaacGym），就需要重写大量网络与协议胶水代码。

阶段四：架构质变——通用语义化 VLA 会话与仿真解耦（2026.09.10 ~ 2026.09.15）

这是 vla_test 分支最辉煌的架构演进，彻底重塑了 TeleFuser 的服务形态：

  • 4e44652 feat(vla): add semantic action session framework：构建了全新的 telefuser.vla 顶层抽象。提出 绝不以张量维度盲猜动作含义 的原则，定义了强类型的 ActionSpaceSpec 和 ObservationSpaceSpec，解耦了策略模型（VLAPolicy）与机器人本体（EmbodimentAdapter）。
  • d6383a4 feat(vla): add replica-backed session serving：对底层的 PipelinePool 进行了突破性改造。在保留传统无状态 acquire() 任务调度的同时，扩展了具有显存/进程亲和性的有状态会话租约（open_session / acquire_session / close_session），保证控制流独占与状态隔离。
  • 9504db8 feat(vla): complete generic session integration：构建了通用的 /v1/vla/session WebSocket 双向协议，采用标准 JSON 封装 Base64 编码的紧凑张量，支持 OPEN、PREDICT、RESET、CLOSE 全生命周期控制与超期丢弃（Superseded）。
  • bce0702 / 3d28619：引入纯 Python、无厚重环境依赖的 MuJoCo 本地快速验证路径，并提供客户端 Chunk 状态机（SimulatorChunkRuntime）。
  • 733aad3 refactor(vla): retire legacy RoboTwin inference endpoint：果断废弃并移除了过往紧耦合的 RoboTwin 专用 MessagePack 服务端，正式宣布进入标准化、通用语义会话时代！

3. 架构对比：早期 TeleFuser vs 当前现行架构

从 main 到 vla_test 的淬炼，TeleFuser 的项目形态发生了结构性跃升。下表总结了关键维度的演化对比：

架构维度 早期项目架构 (Pre-VLA Baseline) 当前现行架构 (Current VLA-Ready)
模型模态覆盖 侧重单向离线生成的视频模型 (Wan2.1, LTX-Video, HunyuanVideo) 与文本图像生成。 全模态融合矩阵：离线扩散视频 + 交互式流式世界模型 (LiveKit WebRTC) + 具身智能闭环控制 (VLA WebSocket)。
服务池与会话调度 纯无状态调度：PipelinePool 仅支持 acquire() / release()。多个请求彼此孤立，无持久化上下文。 双模会话池化：既支持无状态任务队列，又支持副本亲和会话租约（Session Lease），通过 session_id 锁定工作进程，断连自动回收。
动作与传感器契约 弱契约或硬编码：直接透传无物理含义的张量（如 [50, 55]），上下游依赖隐式约定，容易因坐标系或关节顺序错位而炸机。 强类型语义契约：引入 ActionSpaceSpec 与 ObservationSpaceSpec。在会话建立阶段自动校验坐标系、单位、控制频率与归一化方式。
仿真器/外部依赖边界 仿真依赖反向污染服务端：推理服务曾直接引用特定仿真库与私有 RPC 协议（如 MessagePack）。 传输中立与零污染：服务端仅保留纯 PyTorch 核心；仿真器作为客户端通过 WebSocket 交互，配套轻量无依赖的适配层。
执行与加速引擎 基本依赖 PyTorch Eager 模式，小尺寸短序列推理由于 CUDA Kernel 启动开销而遭遇瓶颈。 动静结合混合编译：动态多模态前缀（Eager）+ 固定去噪循环（CUDA Graph），深度结合 SDPA、Sol-Attn 及 FP8/NF4 量化。
动作时序状态机 无时序概念：下游拿到数据后直接执行，网络抖动或丢包时可能执行过期动作。 客户端时序状态机：SimulatorChunkRuntime 严格跟踪 PENDING、READY、EXECUTING、SUPERSEDED，杜绝执行陈旧指令。
💡 核心架构启示
在具身模型中，“推理速度”并不等同于“服务性能”。真正重要的是时钟域同步、最新观测抢占（Supersede）以及对齐的语义动作空间。当前架构成功将控制论的状态机与现代高性能深度学习 Serving 融为一体。

4. 新模型接入实战：标准化 6 步作业流程（SOP）

在当前经过重构的架构下，无论是接入新的具身策略（如 OpenVLA、Octo、RoboCat）、视频生成模型，还是实时世界模型，开发者均应遵循以下 6 步标准作业程序：

Step 1: 模型算子实现 ➔ Step 2: 流水线编排 ➔ Step 3: 语义契约适配 (telefuser/models) (telefuser/pipelines) (telefuser/vla 或流协议) ⬇ ⬇ ⬇ Step 4: 服务池集成 ➔ Step 5: 阶梯式对齐测试 ➔ Step 6: Cookbook 与示例 (telefuser/service) (tools/validation) (examples/新模型)

第一步：模型底层构建与权重加载 (telefuser/models/<model_name>/)

  • 模型定义：实现核心神经网络模块（DiT / Transformer / VAE / 策略网络）。
  • 统一权重解析：实现安全高效的 Safetensors 加载器（支持分片索引映射与键名重映射），避免上游 PyTorch Lightning 或特定框架的代码绑定。
  • 注意力加速选择：显式适配 TeleFuser 统一的 Attention 接口（标准 PyTorch SDPA、SageAttention 或适用于 H100 的 Sol-Attn）。

第二步：流水线编排与加速策略 (telefuser/pipelines/<model_name>/)

  • 阶段式编排（Stage-based）：将推理切分为清晰的生命周期（如条件编码、潜在表示采样/去噪、解码）。
  • CUDA Graph 优化：对于固定步数与维度的去噪循环，提供可选择的 CUDA Graph Capture 封装，降低每步 Launch 时延。
  • 显存优化选项：实现 CPU 异步卸载（Offload）或在线量化适配（TorchAO / bitsandbytes）。

第三步：领域语义契约适配（如为具身 VLA 模型）

from telefuser.vla.contracts import ActionSpaceSpec, ObservationSpaceSpec, ModelActionChunk
from telefuser.vla.policy import VLAPolicy

class NewModelVLAPolicy(VLAPolicy):
    def __init__(self, pipeline):
        self.pipeline = pipeline

    @property
    def action_space(self) -> ActionSpaceSpec:
        # 必须显式声明维度名称、单位、坐标系及归一化配置
        return ActionSpaceSpec(
            representation="joint_positions",
            dimension_names=("joint_1", "joint_2", ..., "gripper"),
            units=("rad", "rad", ..., "m"),
            coordinate_frame="base_link",
            control_hz=20.0,
        )

    def predict(self, observation, task, ...) -> ModelActionChunk:
        # 执行推理并封装为标准的 ModelActionChunk
        ...

若是不同型号的机器人本体，则只需实现对应的 EmbodimentAdapter 进行动作逆归一化或坐标变换，绝对无需修改模型主体。

第四步：服务池集成与会话支持 (telefuser/service/)

  • 协议注册：在 telefuser.service.core.pipeline_contract 中注册请求/响应的数据类型规范。
  • 支持 Session Lease：如果是持续控制模型，为 Pipeline 提供 get_vla_provider() 工厂方法，使其能被 PipelinePool.open_session() 识别并提供专属 worker 绑定。

第五步：阶梯式四级对齐与发布验证 (tools/validation/ & tests/unit/)

验证梯队 验证目标 通过准则 (Acceptance Criteria)
L1: 单元测试 基础组件、参数加载器、协议序列化无语法与类型错误。 CPU 快速单元测试全绿通过。
L2: 官方对齐 (Parity) 与官方原始实现（如 HuggingFace / 官方源码）进行逐层 Tensor 对齐。 在 BF16 精度下，最终输出绝对误差 max_abs < 1e-4（确定性模式下追求 0.0）。
L3: 运行时 Benchmark 统计端到端耗时、显存峰值（VRAM）、首帧延迟（TTFT）。 相比官方原版实现具备性能与显存优势。
L4: 故障注入与压力测试 模拟网络超时、连接意外中断、乱序观测注入。 服务器稳定抛出标准错误码，Worker 自动重置并回收资源，无显存泄露。

第六步：标准化 Cookbook 与工程范例 (examples/<model_name>/)

在 examples/ 目录下建立独立的模型目录，包含：

  1. <model>_inference.py：最精简的单文件 Python 直推演示。
  2. <model>_service.py：启动高性能 Serving 或 WebSocket 会话服务的标准入口。
  3. README.md：遵循 TeleFuser Cookbook 统一规范，详述环境安装、模型权重下载指引与可复现基准。

5. 总结与未来演进展望

回顾 vla_test 分支的建立与完善过程，这不仅是一次针对单一模型（LingBot-VLA v2）的功能集成，更是 TeleFuser 从传统的“多模态内容生成引擎”向“下一代通用具身与物理世界智能基础设施”迈进的关键里程碑。

在这一过程中，我们固化了以下几项不可动摇的工程信条：

  • 坚持高标准数学对齐：所有优化前必须有严格的 Parity 黄金基线护航，优化决不以牺牲生成精度为代价。
  • 推崇语义明确性：绝不在系统内部传递语义模糊的高维张量，动作与传感器必须自描述。
  • 坚决解耦仿真与推理：让推理专注算力极致释放，让仿真专注物理动力学模拟，通过简洁明了的 WebSocket/WebRTC 协议连接彼此。

随着该分支功能的逐步沉淀与回流主干，TeleFuser 将以更开放、更敏捷的姿态迎接更多端到端机器人大模型、长时程世界模型与复杂具身场景的挑战！
